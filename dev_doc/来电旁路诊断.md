# 来电旁路对照测试

用于排查：SIM 插在手机中能正常接听，放到开发板却提示忙音或无法接通，来电诊断也没有观察到振铃上报。

`sms_forwarder_uartdiag_ota_v版本.bin` 是单独构建的诊断包。它保留已存 WiFi、网页、OTA、UART 接收和手动 AT；自动指令仅限 `AT` 握手，不自动执行 SIM 解锁、CGACT、CLIP、短信配置、身份/注册轮询、推送或定时任务。它不是来电修复包。

## 测试步骤

1. 在原固件网页「固件升级」上传同版本的 `uartdiag_ota` 包。
2. 升级后整机断电再上电，避免沿用上一会话的 PDP 等运行状态；无需恢复出厂配置。
3. 重新打开网页，确认固件版本带有「UART旁路诊断」标识，系统日志出现「旁路 AT 已就绪」。
4. 等待模组完成驻网。在 AT 终端手动执行 `AT+CEREG?`；注册状态为 1 或 5 只证明 EPS 驻网，不证明语音业务可用。
5. 点击「来电诊断（60秒）」，再点一次「信号」或执行 `AT+CSQ`。系统日志应记录 `来电诊断 UART：+CSQ ...`，用它确认采集链路工作。
6. 用另一部手机拨入一次，保存从诊断开启到结束的完整系统日志，并记录拨入时刻和主叫侧的提示。
7. 测试后上传普通 `sms_forwarder_ota_v版本.bin` 恢复短信与推送功能。`full` 包用于从地址 `0x0` 整机刷写，不用于网页 OTA。

旁路包不运行短信处理任务，因此观察的是 `来电诊断 UART`，不会发送来电推送。诊断只记录上报名称、长度、字段数，最多 60 秒/64 条，不输出参数正文、号码或短信。

## 如何解释结果

| 对照结果 | 支持的排查方向 |
| --- | --- |
| 普通固件没有来电上报，冷启动后的旁路包出现振铃或新的厂商上报 | 普通固件的初始化或后台操作可能影响该模组，需要继续逐项比对指令 |
| 两个包都没有来电上报，但同卡放手机正常接听 | 继续核对模组语音注册、固件能力/开启步骤、上报接口和板级连接；不能直接归因于推送渠道 |
| 出现未知的厂商上报名称 | 根据对应固件手册或厂商示例适配，不能仅凭名称臆造号码与呼叫状态 |

断电不会自动清除模组内部已有的持久配置。即使旁路包也无法观察到来电，仍不能据此断言硬件永久不支持语音；需要厂商提供适用于完整型号及当前模组固件的可复现步骤。
